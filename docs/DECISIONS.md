# Решения по финансовому учёту

Журнал принятых решений: что выбрано, кем и почему. Номера Б-N — из
[FINANCE_AUDIT.md](FINANCE_AUDIT.md). Старые решения (до 2026-10) — в `HANDOVER.md`,
разделы 5 и 7; здесь только то, что принято в ходе переделки ОПиУ/ОДДС.

## 2026-10-07 — ответы владельца на вопросы аудита

| № | Вопрос | Решение |
|---|---|---|
| D-1 | Амортизация (Б-3) | **Вводим.** Капвложения в ОПиУ попадают только амортизацией. |
| D-2 | Расходы по периоду (Б-4) | **Добавляем** у траты поле «за какой месяц»; ОПиУ — по нему, касса — по дате оплаты. |
| D-3 | Налоги (Б-9) | **Налог 4 %.** Отдельная строка ОПиУ ниже операционной прибыли. |
| D-4 | Проценты по займам (Б-9) | Проценты уплаченные — в ОДДС **операционная деятельность**; в ОПиУ — ниже операционной прибыли. |
| D-5 | Пересчёт кассы (Б-2) | Недостача/излишек **входит в ОПиУ**; первое приведение к факту — отдельной операцией «ввод начального остатка», в поток не входит. |
| D-6 | Переводы (Б-1) | Ввод **не меняем** — остаются две ручные записи. |
| D-7 | Онлайн-заказы (Б-5) | До подтверждения оплаты **не выручка** и не долг. |
| D-8 | Признание выручки (Б-15) | **Оставляем по дате заказа** (статус выдачи не ведётся: 98 из 101 заказа «Готовится»). |
| D-9 | Валюта | **Только сом.** Мультивалютность не делаем. |

Следствия, которые вытекают из решений без выбора (фиксирую, чтобы не потерялись):

- **D-6 → переводы вне потока.** Раз ввод не меняется, ОДДС показывает переводы
  отдельной строкой ВНЕ чистого денежного потока. Если две половины перевода не
  сошлись (внесли только одну), разница видна строкой «Переводы не сведены» с
  предупреждением — а не прячется в потоке.
- **D-3 → профит всех экранов уменьшится на 4 % выручки.** «Сводка», ОПиУ, график по
  дням и «Обзор» показывают одну и ту же чистую прибыль — уже после налога.
- **D-1 → «станок не делает месяц убыточным» (решение 24.08) соблюдается:** вместо
  разового списания — равные доли по месяцам.

## 2026-10-07 — план подтверждён с поправками владельца

Где поправка противоречит `FINANCE_PLAN.md`, действует поправка.

| № | Решение |
|---|---|
| D-10 | Налог: **4 % от выручки месяца нетто возвратов**, по начислению. Строка «Налог (4 % от выручки)». Ставка хранится **историей с датой начала действия** — смена ставки не пересчитывает прошлые месяцы. Уплата — тратой вида «Налог (уплата)», в ОПиУ не идёт. |
| D-11 | Сверка «прибыль → поток» получает строку **«Изменение сдачи клиентам»** (`change_due` — деньги в кассе, но обязательство). Цель: «Не объяснено» = 0 для всех месяцев с октября 2026. |
| D-12 | Откаты оплат (UNPAY) — **не реализовывать, пока владелец не выберет вариант** (описание — FINANCE_AUDIT.md, раздел 7). |
| D-13 | Амортизация: **порог капитализации в настройках** (ниже порога — сразу расход); срок улучшений цеха **не больше остатка аренды** (настройка «аренда до», не задана — 60 мес.); оборудование — 60 мес.; поле **«амортизировать до месяца»** (выбытие/поломка) — после него не начисляется, прошлое не меняется; старт **со следующего месяца**; последний месяц добирает округление, сумма долей = цене. |
| D-14 | Онлайн-заказ: `created_at` **не перезаписывается**; отдельное поле «дата признания выручки», ставится при подтверждении оплаты; продажа и себестоимость в одном периоде. |
| D-15 | Потери материала (брак, недостача) — **в блоке себестоимости, до валовой прибыли**, отдельной строкой. |
| D-16 | Плитка «Выручка»: «Сколько заказов оформили за месяц (включая в долг и предоплаты)». Одна цифра — одно имя на всех экранах. Подсказка к «за какой месяц»: предоплату на несколько месяцев разбивать на отдельные траты. |
| D-17 | Работа поэтапно, коммит-черновик на каждый этап, **не в main**, без пуша и выкладки. |

## 2026-10-07 — решения по ходу этапа 1 (без выбора владельца, следуют из принятых)

| № | Решение | Почему |
|---|---|---|
| D-24 | Онлайн-заказ признаётся продажей при **полной** оплате — и шлюзом, и в кассе (`/pay/`); в тот же момент списывается склад. Частичная оплата онлайн-заказа — аванс: не выручка, не долг. | D-7/D-14. Заодно закрыта найденная дыра Б-17 (см. аудит): онлайн-заказ, оплаченный в кассе, становился «Оплачено», а склад не списывался вовсе. |
| D-25 | Перенос даты заказа двигает дату признания у обычного заказа; у онлайн-заказа — нет (там это день подтверждения оплаты, факт). | D-14: `created_at` и признание — разные вещи. |
| D-26 | Ограничение срока арендой — только у встроенного вида «Улучшение цеха»; свои виды в «Инвестициях» — как оборудование, 60 мес. | Свой вид система не может отличить от станка. |
| D-27 | Роль своего вида выводится из блока («Инвестиции» → капвложение, остальное → расход); выбора роли в форме нет. Проценты и налог — только встроенные виды блока «Проценты и налоги». | Б-10: промежуточного «никуда» быть не должно. |
| D-28 | Старые расходы, внесённые прямо в кассу (статьи EXPENSE/SALARY без траты, до 27.09), идут в ОПиУ строкой «Расходы, внесённые прямо в кассе» по дате оплаты. | Иначе выпадали бы из прибыли совсем. На копии прода их 0. |
| D-29 | Статья кассы «Прочее» — операционная деятельность ОДДС, в ОПиУ не идёт; в сверке — своей строкой «Прочие движения кассы», а не в «Не объяснено». | Природа записи неизвестна; показать честно, а не прятать. |
| D-30 | Встречная запись при отмене прихода/накладной/удалении материала — та же статья «Оплата поставщику», приходом, сегодняшним днём; только по записям системы. | Б-13; ручную запись человек сделал сам. |
| D-31 | Месяц везде хранится первым числом; «за какой месяц», месяц выбытия и начало ставки проверяются замком по **всему месяцу**: замок «по 15.10» закрывает октябрь для этих полей. | ОПиУ — помесячный: часть месяца закрыта — прибыль месяца уже принята. |
| D-32 | Миграция 0014 даёт своим видам со снятым «входит в прибыль» вне «Инвестиций» роль OPEX. Поэтому **перед выкладкой** обязательна проверка прода (чек-лист в FINANCE_PLAN.md, раздел 7); нашлись — стоп и вопрос владельцу. | Требование владельца; угадывать миграцией нельзя, а падать при старте контейнера — нельзя тем более. |

## 2026-10-07 — решения по ходу этапа 2 (расчёты)

| № | Решение | Почему |
|---|---|---|
| D-33 | **Отчёт за любой период — сумма дней.** То, что ложится в прибыль месяцем, раскладывается по дням: расход, оплаченный в своём месяце, — днём оплаты (постоянные — поровну по дням, как было в графике); оплаченный в другом месяце — поровну по дням «своего» месяца; амортизация — поровну; списание выбывшего — последним днём месяца; налог — от выручки дня. | Так прибыль месяца, года, произвольного отрезка и графика по дням — одно число по построению, а не по сверке тестом. |
| D-34 | **Правило округления** — одно, в `finance/reports/money.py`: деньги до тыйына, половина вверх, один раз на итоге; раскладка на части (амортизация, дни, налог по дням) — части вниз до тыйына, последняя добирает остаток; маржа — до десятой. | Требование «округление явное и одинаковое везде»; сумма частей всегда точно равна целому. |
| D-35 | «Весь период» кончается последним днём текущего месяца. | Текущий месяц входит целиком — как в отчёт за этот месяц; будущие месяцы (амортизация вперёд) — нет. |
| D-36 | Налог месяца линеен от выручки и при отрицательной выручке месяца (возвратов больше продаж) тоже отрицателен. | Иначе год ≠ сумме месяцев. Случай почти невозможный; если владелец хочет «не ниже нуля» — одна строка. |
| D-37 | Неоплаченный онлайн-счёт не числится долгом **нигде** (`Receipt.debt` = 0, списки и карточки клиентов), но оплатить его в кассе можно. | D-7: «не выручка и не долг». |
| D-38 | В сверке долг клиентов и их деньги у нас (сдача, предоплаты) считаются **по клиенту**: выручка по его чекам минус его деньги по кассе. Долг по одному заказу и сдача по другому у одного клиента взаимно гасятся. | Зачёт сдачи в новый заказ денег не двигает и не записан по чекам — внутри клиента он сам себя гасит; иначе «Не объяснено» ≠ 0. |
| D-39 | Строка сверки «Рост запасов» — по потоку: пришло − продано − списано. Разрыв склада (остаток без прихода, старые списания без себестоимости) в сверку не входит. | Разрыв — не деньги и не прибыль; он остаётся в цепочке склада «Сводки». |
| D-40 | Строки «Сводки»: расход и проценты — **начислено** («за какой месяц»), покупки в «Инвестициях», уплата налога, закуп, долг материала — **оплачено** (по дате траты). Блок «Инвестиции» показывает, сколько из покупок стало активом и сколько — расходом. Окно вида открывается с тем же отбором (`?basis=accrued`). | Строка блока и окно с её тратами должны давать одну сумму. |
| D-41 | Покупка в «Инвестициях», заведённая мимо формы (скрипт, тест), проходит то же правило порога — в `ExpenseEntry.save`. | Единое правило; раньше станок за 300 000 из скрипта становился расходом месяца. |

На копии прода от 19.09 после этапа 2: чистая прибыль сентября **83 322,48 — как и
до переделки** (налога в сентябре нет, потери переехали в себестоимость, итог тот
же); валовая прибыль стала 170 199,48 (после потерь). В сверке сентября «Рост
долга поставщикам» 1 722 976,84 — это закуп до 19.09, оплаченный мимо кассы
(решение заказчика 19.09); «Не объяснено» — 0.

Следствие, принятое без выбора: покупка вида «Инвестиции» **ниже порога** идёт в
операционные расходы ОПиУ и в **операционную** деятельность ОДДС — в
инвестиционную по МСФО (IAS 7, п. 16) попадают только траты, создающие актив.
