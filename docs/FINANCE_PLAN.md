## 1. Структура отчётов

### ОПиУ (метод начисления, по месяцам года + итог года)

```
Выручка                                    по дате заказа, возврат — днём возврата
   материал · резка · прочие работы
− Себестоимость проданного                 FIFO-снимок
   материал · расходники услуг
= Валовая прибыль                          + валовая маржа, %
− Операционные расходы                     по «за какой месяц» (D-2)
   Материалы (транспорт, свои) · Постоянные · Переменные — по статьям
− Списание материала (брак, недостача)
− Недостача / + излишек кассы              (D-5)
= EBITDA                                   + маржа, %
− Амортизация                              (D-1)
= Операционная прибыль                     + операционная маржа, %
− Проценты по займам                       (D-4)
− Налог 4 %                                (D-3)
= Чистая прибыль                           + чистая маржа, %
Справочно: капвложения месяца (в прибыль не входят — только амортизацией)
```

### ОДДС (кассовый, прямой метод)

```
Остаток на начало
Операционная деятельность
   поступления от клиентов (нетто оплат, сдачи, откатов) · возвраты клиентам
   оплата поставщикам · расходы по статьям · налог уплаченный · проценты уплаченные
   недостача / излишек кассы
Инвестиционная деятельность
   покупка оборудования · улучшение цеха
Финансовая деятельность
   вложения / изъятия владельца · займы получены / погашены (тело)
= Чистый денежный поток                    только три блока
Вне потока (не меняют итог денег):
   переводы между кассой и банком          (+ «не сведены: N», если половины не сошлись)
   ввод начального остатка                 (D-5)
Остаток на конец                           = начало + поток + вне потока; по счетам
```
Блок «Прочие движения» исчезает: статья кассы «Прочее» относится к операционной
деятельности (ручные записи, видно строкой «Прочее»).

### Сверка «чистая прибыль → чистый денежный поток» (новая вкладка/блок под ОДДС)

```
Чистая прибыль
+ Амортизация                                       деньги не уходили
− Рост долга клиентов (+ снижение)                  выручка без денег / оплата старых долгов
− Рост запасов на складе                            закуп − себестоимость − списано
+ Рост долга поставщикам                            материал взят, не оплачен
+ Расходы начислены, не оплачены (− оплата прошлых) D-2: «за сентябрь» оплачено в октябре
+ Налог начислен, не уплачен
− Капвложения                                       станок оплачен целиком
± Финансовая деятельность                           владелец, займы
± Не объяснено                                      дыры в данных (должно быть 0)
= Чистый денежный поток (сверяется с ОДДС)
```
Каждая строка — разница за месяц, поэтому история до ведения кассы на месяцы после
неё не влияет. На сентябре прода «Не объяснено» будет ненулевым (закуп до 19.09 мимо
кассы, решение заказчика 19.09) — строка это и покажет; с октября должна быть 0.

### «Обзор» (один экран, выбранный месяц, по умолчанию текущий)

Четыре главные плитки, у каждой — период и «сом» в подписи, подсказка (ⓘ) и
изменение к прошлому месяцу (сумма и %):

| Плитка | Подпись простыми словами |
|---|---|
| Выручка | «Сколько заказов сделали за месяц (включая в долг)» |
| Чистая прибыль + маржа | «Сколько заработали после всех расходов и налога» |
| Чистый денежный поток | «Насколько денег стало больше или меньше» |
| Деньги на конец месяца | «Сколько денег в кассе и на счёте», в т.ч. наличные / банк |

Под ними — короткая строка «почему прибыль ≠ деньгам» (2–3 крупнейших строки сверки,
ссылка на полную сверку). Существующие блоки «Обзора» (материал, склад, на исходе)
остаются ниже. «Получено» в «Обзоре» переводится на кассовую книгу (Б-6); «сколько из
выручки месяца уже оплачено» остаётся отдельной подписанной цифрой.

Подсказки у терминов — и в таблицах ОПиУ/ОДДС/сверки (валовая прибыль, EBITDA,
амортизация, маржа, поток, перевод…). Одна цифра — одно имя: «прибыль до расходов»
везде становится «валовая прибыль (прибыль до расходов)».

## 2. Модель данных

### Единый справочник категорий — `finance/chart.py`
Один модуль, где каждой категории сопоставлены строка ОПиУ и строка ОДДС:
- **виды расхода** (`ExpenseKind`) — по новому полю `role`;
- **статьи кассы** (`CashEntry.Article`) — таблицей в коде (сейчас `_BY_ARTICLE`);
- **системные строки** — выручка, себестоимость, списание, амортизация, налог.

Тест-инвариант: у каждого вида и каждой статьи есть строка в обоих отчётах (или явное
«не участвует»), ни одна не теряется.

`ExpenseKind.role` (заменяет связку `block` + `in_profit` как источник истины для
отчётов; `block` остаётся группировкой операционных расходов):

| role | ОПиУ | ОДДС | Кто |
|---|---|---|---|
| `OPEX` | операционные расходы, по блоку | операционная, своей строкой | аренда, зарплата, транспорт, свои |
| `CAPEX` | только амортизация | инвестиционная | оборудование, улучшение цеха |
| `INTEREST` | проценты ниже опер. прибыли | операционная (D-4) | новый встроенный «Проценты по займам» |
| `TAX` | — (налог начисляется сам, 4 %) | операционная «налог уплаченный» | новый встроенный «Налог (уплата)» |
| `INVENTORY` | — (уйдёт себестоимостью) | операционная «поставщикам» | старые «Закуп материала» |
| `NOT_CASH` | — | — | «Долг материала» |

Свой вид создаётся с `role=OPEX` (или `CAPEX` в «Инвестициях»); флаг «входит в прибыль»
в форме исчезает — промежуточного «никуда» больше нет (Б-10).

### Изменения моделей (все миграции обратимые)

| Миграция | Что | Данные | Откат |
|---|---|---|---|
| finance/0013 | `ExpenseKind.role`; `ExpenseEntry.period` (первое число месяца, null); `ExpenseEntry.useful_life_months` (null); `FinanceSettings.tax_rate` (4.00) | — | удаляет поля |
| finance/0014 | role по существующим видам: Инвестиции → CAPEX, «Закуп» → INVENTORY, «Долг» → NOT_CASH, остальное с `in_profit=True` → OPEX; `period` = месяц `spent_at`; `useful_life_months` = 60 у CAPEX; встроенные виды TAX и INTEREST | только заполнение | обнуляет поля, удаляет новые виды без трат |
| finance/0015 | `CashEntry.Article.OPENING` («Ввод начального остатка»); `CashEntry.roll` → SET_NULL | choices, на Postgres SQL — no-op | возврат choices / CASCADE |

Последствия:
- **Своих видов со снятым «входит в прибыль» вне «Инвестиций»** миграция не угадает.
  На копии прода от 19.09 их нет; перед выкладкой — посчитать на проде командой. Если
  найдутся — остановиться и спросить, OPEX это или CAPEX.
- `in_profit` остаётся в базе (для отката), но отчёты его больше не читают.
- Колонки и данные — разными миграциями (урок 0008: Postgres не даёт строить индекс в
  транзакции, где таблицу уже правили).
- Существующие записи COUNT (если есть на проде) начнут попадать в ОПиУ — посчитать до
  выкладки; если там первое приведение кассы, перевести его в OPENING.

### Поведение
- **Трата:** поле «за какой месяц» по умолчанию = месяц даты оплаты (вводить ничего не
  надо); у капвложений — «срок службы, мес.» (по умолчанию 60).
- **Амортизация:** линейно, `сумма / срок` в месяц, начиная со следующего месяца после
  покупки, в копейках; последний месяц добирает остаток округления, чтобы за срок вышла
  ровно сумма покупки. Считается, не хранится.
- **Налог:** `ставка × выручка месяца`, до копейки. Уплата — тратой вида «Налог
  (уплата)» в «Финансах» (уходит в кассу, в ОПиУ не идёт). Смена ставки задевает
  прошлые месяцы → подчиняется замку периода, как смена роли вида.
- **Онлайн-заказ (D-7):** неоплаченный не входит ни в выручку, ни в долг; при
  подтверждении дата заказа становится днём подтверждения — продажа и себестоимость в
  одном периоде.
- **Касса:** ручная «Оплата поставщику» убирается из списка (Б-7) — платят из долга в
  «Финансах»; уже внесённые остаются строкой. Удаление партии с оплатой пишет
  встречную запись сегодняшней датой, а не стирает (Б-13).

## 3. Слой расчётов

`finance/reports/` — вся логика, обработчики только читают параметры и отдают ответ:

| Модуль | Что | Кто использует |
|---|---|---|
| `pnl.py` | `pnl(d_from, d_to)` → все строки ОПиУ одного периода; `pnl_year` | ОПиУ, «Сводка», «Обзор», график по дням |
| `cashflow.py` | ОДДС за период / год, остатки, переводы | ОДДС, «Обзор» |
| `bridge.py` | сверка прибыль → поток | вкладка сверки, «Обзор» |
| `depreciation.py` | график амортизации по покупкам | `pnl` |

«Сводка» (`FinanceReportView`) берёт денежные показатели из `pnl()` вместо своих
формул; блоки резки/склада/обрезков переезжают в модуль как есть, без изменения
логики. Дубль `_losses` удаляется. `DashboardView` и `DailyReportView` — так же.

## 4. Этапы реализации (после каждого — полный прогон тестов и отчёт)

1. **Данные:** миграции 0013–0015, справочник `chart.py`, поля в сериализаторах и
   формах трат; тесты миграций (вперёд/назад) и справочника.
2. **Расчёты:** `finance/reports/*`, онлайн-заказы, касса (OPENING, SUPPLY, партии),
   перевод «Сводки»/«Обзора»/графика на общий слой; юнит-тесты на каждую формулу.
3. **Интерфейс:** ОПиУ с новыми строками и маржами, ОДДС с блоком «вне потока», вкладка
   сверки, новый верх «Обзора», подсказки, переводы ru/ky/en; проверка в браузере.
4. **Тесты-сценарий:** набор операций за квартал с итогами, посчитанными вручную в
   `finance/tests_golden.py` (ОПиУ, ОДДС, остатки по счетам, сверка) — совпадение до
   копейки; инварианты: начало + поток (+ вне потока) = конец; перевод не меняет итог
   и поток; сумма строк = итог; прибыль «Сводки» = ОПиУ = «Обзор» = сумма графика по
   дням; «Не объяснено» = 0.
5. **Проверка на копии прода** (`chpu_audit_0926`): прогон отчётов, сверка «до/после»
   по каждой изменившейся цифре с объяснением.

Выкладка на прод и коммит — отдельно, по команде.

## 7. Чек-лист перед выкладкой на прод (добавлено на этапе 1)

Выполнить на ПРОДЕ до `migrate` (команды — в контейнере `db`, `psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"`).
Любая ненулевая строка в пунктах 1–2 — стоп и вопрос владельцу.

```sql
-- 1. Свои виды со снятым «входит в прибыль» вне «Инвестиций» (D-32): OPEX или CAPEX?
select code, name, block from finance_expensekind
 where in_profit = false and block <> 'INVESTMENT'
   and code not in ('MATERIAL_PURCHASE', 'MATERIAL_DEBT');
-- 2. Пересчёты кассы: войдут в ОПиУ (D-5); первое приведение кассы — перевести в OPENING.
select id, happened_on, kind, amount, note from finance_cashentry where article = 'COUNT';
-- 3. Капвложения до октября 2026: получат амортизацию задним числом с месяца после покупки.
select e.id, e.spent_at, e.amount from finance_expenseentry e
  join finance_expensekind k on k.id = e.kind_id where k.block = 'INVESTMENT';
-- 4. Неоплаченные онлайн-заказы: уйдут из выручки и долга (D-7).
select count(*) from sales_receipt where payment_method = 'ONLINE' and payment_status = 'PENDING';
-- 5. Старые расходы прямо в кассе: войдут в ОПиУ по дате оплаты (D-28).
select count(*) from finance_cashentry where article in ('EXPENSE', 'SALARY') and expense_id is null;
```

На копии прода от 19.09 (`chpu_audit_0926`) все пять — нули.
